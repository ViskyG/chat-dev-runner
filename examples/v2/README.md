# Small native calculator projects

Each project provides a finite four-operation calculator, meaningful tests and a
`.runner/project.json` generated by `standard_project`. The manifests select the
initial Python, npm/Vitest, TypeScript and .NET/VSTest recipes. These examples
exercise tools and report formats; they do not enroll a project or start a
Runner service by themselves.

| Project | Enrolled recipe | Program use |
| --- | --- | --- |
| `python-calculator` | Per-run venv, hash-pinned pytest dependencies, JUnit XML | `python calculator.py 12 / 4` |
| `javascript-calculator` | `npm ci`, local Vitest, JUnit XML | `node cli.js 12 / 4` |
| `typescript-calculator` | `npm ci`, local TypeScript `--noEmit`, local Vitest/JUnit | Import `calculate` from `calculator.ts` |
| `csharp-calculator` | SDK pinned by `global.json`, locked NuGet restore, explicit VSTest/TRX | `dotnet run --project Calculator -- 12 / 4` |

Tests cover arithmetic, division by zero and non-finite input. Argument tokens
and report paths are declared explicitly in each manifest. Use the project's
selected native toolchain; do not install dependencies into a global Python or
npm environment. npm and NuGet lockfiles are included. The Python lock lists
exact distribution hashes, including compatibility dependencies for Python 3.10.

The C# SDK pin reflects the observed qualification target, not a claim that every
SDK is interchangeable. The projects contain approved example code, including
package preparation scripts selected by their pinned dependencies. Native mode
runs with the ordinary user's host access; a per-run directory is not a sandbox.

Qualification results and exact boundaries are recorded in
[`verification/implementation/GP-06/toolchains`](../../verification/implementation/GP-06/toolchains).
Java/Maven are part of the planner's initial recipe family, but no Java SDK or
Maven binding was available on the observed target; no Java execution is claimed.
