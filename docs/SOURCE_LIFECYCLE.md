# Managed local source lifecycle (EP-02)

EP-02 implements local source operations on runner-owned repositories. It does not register production command handlers or execute project code. EP-05 will connect finite admitted commands to these steps after EP-03 containment and EP-04 Drive transport are verified.

A project repository is a private bare Git repository at `managed_root/<project_id>/repo.git`. Each workspace is a linked checkout at `managed_root/<project_id>/workspaces/<workspace_id>` with its own branch, HEAD, durable source generation and archive state. `SourceService` requires a RUNNING EP-01 operation and its exact repository or workspace lock before a mutating step. It records durable effect intent before Git writes; an uncertain effect retains its lock for reconciliation. SQLite migration 3 stores project/workspace source identities, immutable snapshot facts and immutable run-to-snapshot bindings. The API and command wire schemas remain v1.0.

`create_new_source` makes an empty local main commit. `import_local_source` accepts only an opaque handle issued through the authenticated local API for a configured allowed root; no roots are enabled by default. It pins the granted directory while cloning committed refs into a separate managed repository and leaves dirty edits and untracked files in the original checkout untouched. These local steps do not create a GitHub repository, apply a template, provision Drive documents or execute the import.

`create_workspace_source` checks out an exact commit on a distinct branch. `retarget_workspace_source` requires an idle clean workspace, the registered generation/HEAD/branch and an unoccupied target branch at its declared commit. `fetch_source` only updates tracking refs from an explicitly allowed local bare remote in this offline packet. `sync_workspace_source` requires a clean fast-forward to the exact command-approved fetched commit and never fetches implicitly. Both branch change and sync refuse ignored as well as ordinary untracked files, so Git cannot overwrite private ignored bytes. `inspect_workspace_source` reports live dirty/ahead/behind/diverged status beside the durable identity and reveals external HEAD/branch changes. `archive_workspace_source` marks a workspace inactive and retains its checkout, including any dirty files; deletion flags are refused.

Changesets are validated against the complete base commit, allowed paths and expected file hashes, then applied through a private no-checkout Git index. Clean VERIFY captures the current committed tree; dirty VERIFY requires explicit current file/hash approvals. No snapshot step updates the human's editable checkout. A private ref `refs/cdr/snapshots/<snapshot_id>` and fsynced mode-0600 manifest retain the exact commit, tree, provenance, generation, capture fingerprint and included paths. An edit after capture makes the snapshot stale without changing it. A fault between Git staging and database recording leaves the ref/manifest and an uncertain effect for operator reconciliation.

A staged snapshot alone is never publication authority. `SourceRegistry.bind_tested_run` accepts only an immutable schema-valid completed run manifest for the same project/workspace and exact commit/tree, backed by a confirmed source-snapshot effect and an immutable contained-execution attestation. EP-03 records that manifest, attestation and frozen output-file index in one SQLite transaction after its rootless broker completes; incomplete collection and cancellation do not create publication authority. `publication_target` returns the bound retained commit/tree and refuses a missing or changed ref. EP-05 must recheck the workspace generation/HEAD and policy before any branch promotion or provider write. No cloud credentials or user repositories were used in EP-02 acceptance.
