## Authority and refusal evidence

- **Host paths and profile authority.** `runner_app/domain/commands.py::LocalPolicy.authorize` accepts local imports only through registered handles and only owner-approved profiles. `runner_app/git/imports.py` opens an owner-approved root and stores a private pinned handle; the remote command cannot supply an arbitrary host path. `runner_app/git/changes.py::safe_source_path` requires canonical relative source paths and blocks protected/secret components. The JUnit cases `test_export_paths_cannot_escape_or_select_protected_files` (9 parameterized inputs), `test_workspace_cannot_select_unapproved_profile`, and `test_repository_suggestion_cannot_add_or_replace_a_local_grant` passed. This is a source/authority route proof, not a claim that every path on the owner's machine was probed.
- **Hooks, filters, submodules and external object stores.** `runner_app/git/worktrees.py` refuses unsafe Git config, gitlinks, `.gitmodules`, LFS config, filter attributes and object alternates; `runner_app/git/materialize.py` materializes Git objects without checkout filters. The real disposable-Git cases `test_local_import_preserves_dirty_original_and_does_not_run_hooks`, `test_hostile_filter_and_submodule_requirements_are_refused`, `test_managed_checkout_disables_hostile_git_hook`, `test_tracked_lfs_filter_is_refused_before_checkout`, `test_local_import_rejects_object_alternates`, and `test_import_rejects_submodule_tree_and_keeps_evidence` passed. These exercise refusal and nonexecution locally; no live hostile repository was imported into the installed service.
- **Workflow policy and force push.** `runner_app/git/changes.py::safe_source_path` blocks the `.github` component and policy files before staging. `test_protected_source_paths_are_refused_before_staging` passed for `.github/workflows/build.yml` and eight other paths. The authenticated Git transport in `runner_app/git/github_transport.py` constructs fixed HTTPS operations with `push.recurseSubmodules=no`, no force flag, and exact nondefault refs. `runner_app/git/publish.py` checks expected remote head and refuses divergent branches before a normal push. `test_command_fixes_https_no_redirect_proxy_or_force` and `test_known_divergent_branch_never_force_pushes` passed. This audit does not claim authority over out-of-band Git commands issued by the owner.

The evidence supports the narrow EP-07 checklist criterion “No arbitrary host path, submodule/filter/hook execution, workflow-policy escalation or force push” for the installed v1 runner routes. It does not close rootless confidentiality, malicious artifact handling, crash recovery or the remaining host acceptance matrix.
