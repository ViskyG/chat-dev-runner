# EP-06 scenario coverage and evidence

The installed **existing** Drive workspace is authoritative. SC-01's archive-era new-root step is superseded by the owner's attach-existing instruction. No EP-06 check creates a Drive root or runs a provider write. `PASS` means the browser-observable slice of that scenario is verified; `PARTIAL` names the remaining end-to-end criterion. Browser fakes use the real packaged HTML/CSS/modules and intercept only `/api/v1/*`, with command bodies validated against `command.schema.json` before fake 202/409 receipts.

Focused evidence: `browser-e2e.json` **65/65** Chromium checks across all 14 scenarios; `local-process-slice.json` **19/19** checks on a fresh disarmed, no-provider local Uvicorn process; `live-ep05-state-slice.json` **22/22** on the existing disarmed disposable EP-05 state with the actual owner configuration and no Drive/workspace pollers. The latter made three explicit read-only checks: Drive **OK**, GitHub API identity **OK**, and the selected workspace Git remote **OK**, each with an independent timestamp. Only those check POSTs and local-session authentication occurred; no READY command or provider write. The original offline prototype baseline is `baseline-browser.json` **44/44**, and is not counted as verification of this packaged UI.
