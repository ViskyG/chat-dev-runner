## С чего начинать

Для владельца: `01_OWNER_DECISIONS_RU.md` содержит окончательные требования и явно отмеченные инженерные трактовки. Для Codex или Claude точка входа — `00_START_HERE.md`, затем пакет `packets/GP-00.md`. Распаковывать отдельно: этот архив не должен накладываться поверх исходников раннера.

Перед изменением проекта агент предъявляет пронумерованный список с назначением каждого изменения, затронутыми файлами, последствиями отказа, временным обратимым вариантом и способом отката. Применяются только лично одобренные пункты. Полная формулировка запуска находится в `00_START_HERE.md`.

## Что спроектировано

GitHub работает самостоятельно, без обязательного Google/ChatGPT. В репозитории — переиспользуемый командный файл на конкретный раннер. Google Docs остаётся альтернативным каналом с существующим одним командным документом. В обоих случаях автор ставит READY последним действием; раннер сам подтверждает приём и освобождает слот. Никаких локальных команд или кнопок для обычной отправки.

Задания принимаются только при живом наблюдении. Если исполнитель занят, принятые команды ждут FIFO; история офлайн-команд не восстанавливается. Код выбирается текущий в момент начала задачи, после чего фиксируется на весь запуск. После перезапуска уже принятые, но не начатые задачи предлагается сохранять как SUSPENDED_RESTART, а не автоматически выполнять; эта трактовка отдельно обозначена в требованиях.

Нативные Windows/macOS/Linux и контейнерный режим различаются явно. Обычные задачи и shell-команды исполняются с правами пользователя раннера, без обязательного нового системного пользователя. Это не песочница. Первые языки: Python, JavaScript, TypeScript, Java и C#. Compose — отдельный конечный сценарий, Unity — последняя ограниченная проверка.

Результаты добавляются в ту же ветку, которая тестировалась. Отчёт содержит идентичность проверенного снимка, среду, тесты, логи и результаты программы. При конкурентном изменении ветки нельзя возвращать старый код: добавляется только папка результатов. Большие файлы и неотправленные результаты остаются рядом с управляемой копией проекта; опубликованные указатели не выдаются за доступное содержимое файла.

## Навигация по комплекту

- `02_DESIGN.md`–`05_RESULTS_AND_PLATFORM.md`: архитектура, протокол, исполнение и доставка.
- `06_MIGRATION_AND_ROADMAP.md`, `packets/`: порядок интеграции, зависимости и критерии завершения.
- `07_ACCEPTANCE.md`, `acceptance_scenarios.json`: сценарии и проверяемые требования.
- `contracts/`: предложенные схемы и неактивные примеры, не текущие schemas раннера.
- `skills/`: три проекта скилов, каждый с полной русской и английской версией; ещё не зарегистрированы и не установлены.
- `verification/REPORT.md`: результаты реально выполненных проверок и точные ограничения.

Не возвращать отменённые предложения: офлайн-очередь команд, обязательный Google, BUSY вместо живой очереди, отдельную ветку результатов, автоматический LFS/Release, замену нативных тестов WSL-контейнером или новые роли операторов.
