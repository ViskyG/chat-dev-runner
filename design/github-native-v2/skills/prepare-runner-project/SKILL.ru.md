# Подготовка проекта для Chat-Dev Runner
Перевод prepare-runner-project, версия 2.0.0-design. Черновик, не установленный скил.

Применять по явной просьбе подготовить проект. Сначала читать AGENTS проекта и реальные инструкции/возможности установленного раннера. Не предполагать, что v2 уже работает. Выбирать через каноническую навигацию после одобрения и регистрации; не обходить соседние скилы без причины. Этот файл не даёт прав изменять проект или компьютер.

## Обследование
Прочитать исходники и манифесты среды, настройки тестов, соответствующие точки входа, существующий CI и результаты программы. Проверить реальные команды и форматы; одного README недостаточно. Определить язык, фреймворк, пакетный менеджер, нативную ОС/гостевую ОС контейнера, ветку/рабочую область, конкретный runner_id и требуемые файлы. Отсутствие SDK, lockfile или reporter — находка, а не разрешение устанавливать их.

В чате пользователя выдать список изменений. Для каждого: пути и точный замысел правки, зачем она раннеру, что будет без неё, зависимости от других пунктов, риск, исходная версия/идентичность diff, временная обратимая альтернатива и откат. Не переспрашивать решённые вопросы о доверии, каналах и платформах.

## Личное одобрение
Каждый пункт получает PENDING, APPROVED или DECLINED со ссылкой на реальное решение пользователя. Пользователь может одним ответом перечислить несколько одобряемых IDs. Это не разрешает остальные изменения. Общая просьба «подготовь», положительная реакция или созданный агентом approval-файл не заменяют личное согласие по пунктам. При существенном изменении объёма/базы согласовать только изменившийся пункт.

Менять только одобренное. Сохранить чужие правки, untracked-файлы, ветки, CI и фреймворк. Не выполнять скрытый stash/reset, не ставить глобальные зависимости, не добавлять фреймворк или фиктивные зелёные тесты, не выдавать права и не ослаблять критерии. Обычное создание временных файлов/зависимостей в уже одобренном рецепте не требует согласовывать каждый файл заново.

Временный вариант: отдельная рабочая копия/наложение изменений либо одобренный worktree. Оригинал не трогать; записать хеш наложения и проверенного снимка; проверить откат по ожидаемым хешам. Временная правка также требует одобрения. Не выдавать изменённый временный вариант за исходный коммит.

## Проверка договора
Выбрать установленный квалифицированный профиль. Описать test/build/run в cdr-project/2: аргументы/диалект, назначения и форматы результатов, обязательные проверки. Сохранить исходные отчёты: подходящий JUnit, выбранный TRX/MTP для .NET, NUnit на позднем этапе Unity. Неизвестные форматы хранить файлами; не угадывать число тестов из консоли.

При разрешении проверить настоящий успех/провал/отсутствие тестов/ошибку отчёта, обязательные результаты программы, завершение без диалога, версии ОС/инструментов и сбор файлов. Один manifest ещё не означает READY. Указать фактически проверенные ОС/backends/фреймворки; недоступные цели — NOT_QUALIFIED. Подробности экосистем хранить в документации проекта, не дублировать в каждом скиле.

## Передача
Вернуть применённые/отклонённые/ожидающие пункты, точную версию кода и среду, доступные задачи, конкретный слот/раннер, расположение результатов и оставшиеся блокировки. Не предлагать команду, которая скрытно изменит исходники при следующем запуске. Сохранить решения и доказательства в предусмотренных местах проекта. Не устанавливать этот черновик в каноническую библиотеку и не редактировать навигатор без отдельного одобрения ограниченной библиотечной правки.
