# Установка и обновление раннера через Codex / Claude
Перевод install-runner, версия 2.0.0-design. Черновик, не установленная возможность.

Применять по просьбе об установке/обновлении. Прочитать AGENTS проекта, текущий статус, выбранный пакет проектирования и свидетельства существующей установки. При начале реализации сравнить текущий checkout, а не считать прежнюю актуальность вечной. Для Codex и Claude использовать один план, тонкие ссылки входа, не две расходящиеся версии требований.

## Обследование и согласие
Без изменений проверить ОС/архитектуру, обычную учётную запись, существующую службу/процесс, checkout, схему БД, управляемые пути, каналы и выбранные инструменты. Не выгружать секреты в чат/репозиторий. Существующие Drive root/index подключать по точным IDs, не создавать повторно. GitHub-only не требует Google; отсутствие Docker не мешает разрешённому native.

Подготовить отдельные пункты для исходников/конфигурации/схемы, службы/автозапуска, зависимостей, учётных данных/прав и привязки проектов. Указать цель, последствия отказа, риски, точные ресурсы/пути, временный обратимый вариант и откат. Получить личное согласие по каждому пункту. Не создавать скрытно системного пользователя, повышение прав, роли операторов или публичный listener. Нативный режим работает от выбранного владельцем обычного пользователя. Объяснить возможности пишущих участников репозитория; не называть режим песочницей.

## Применение и проверка
По одобренному порядку остановить приём. Зафиксировать выполняющиеся/ожидающие/неопределённые операции. Сделать резервную копию остановленной БД/конфигурации/ссылок на секреты; перед миграцией проверить восстановление на отдельной копии. Сохранить прежние доказательства и точные облачные IDs. Не включать значения секретов в экспортируемые артефакты/копии.

Установить одобренный код, платформенные механизмы и автозапуск пользователя. Для Linux/Windows/macOS нужны собственные реальные проверки; WSL/контейнер обозначаются честно. Начать с контролируемой приёмки, открыть новые сессии слотов без воспроизведения старых READY. Проверить удалённый цикл DRAFT/READY/ACK человеком/чатом, FIFO, текущий код при старте, отмену, реальные pass/fail, результаты/среду, публикацию в ту же ветку и локальный fallback. Проверить обратным чтением живой провайдер; структура файлов этого не доказывает.

Windows требует реальной проверки Job Object/дерева процессов/файлов/блокировок. macOS — групп процессов/launchd/файловой системы. Linux должен сохранить проверенные rootless-маршруты. Отсутствующая машина/инструмент/провайдер — NOT_QUALIFIED и конкретная незавершённая проверка, не фиктивный сертификат. Продолжать независимую одобренную работу, когда возможно.

## Откат и передача
Откатывать остановленную службу на согласованную пару старого бинарника и backup схемы. Не открывать новую БД старым кодом. Неопределённые процессы/внешние эффекты держать до сверки, не запускать принятую команду повторно автоматически.

Вернуть установленную версию/исходный SHA, применённые пункты, реальные IDs/возможности каналов, проверки, пути локальных результатов, пробелы и проверенный откат. После этого обновить правдивые STATUS/checkpoints. Регистрировать двуязычные скилы/навигацию только в рамках одобренной библиотечной правки и проверить привязку установки. Чтение SKILL.md не равно установке. Дополнительный CLAUDE.md может ссылаться на общие инструкции после одобрения изменения. Не добавлять scheduler или автоматическое продолжение моделью.

Ссылки при интеграции: ../../00_START_HERE.md, ../../06_MIGRATION_AND_ROADMAP.md, ../../07_ACCEPTANCE.md. Перед канонической публикацией заменить на устойчивые ссылки проекта.
