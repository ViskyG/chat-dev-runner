# Install or upgrade Runner with Codex / Claude

Enter only on an installation/upgrade request. This design draft is not installed capability. Read the owning project's AGENTS, current status, exact selected design packet and existing installation evidence. Do not assume GitHub/local source parity forever; compare the current checkout when implementation begins. Use one shared plan for Codex and Claude, with thin agent entry references rather than duplicated requirements.

## Read-only preflight and consent
Inspect OS/architecture, ordinary user identity, existing service/process, source checkout, current DB schema, managed paths, configured transports and selected toolchains. Never dump secrets into chat/repository. Existing owner-provided Drive root/index must be attached, not duplicated. A GitHub-only installation requires no Google setup; missing Docker does not block approved native mode.

Prepare numbered change items for source/config/schema, service/startup integration, dependencies, credentials/permissions and project binding. Explain purpose, without-change behavior, risks, exact resource/path scope, a reversible temporary route and rollback. Obtain personal approval for each item; apply only approved changes. No hidden system user, elevation, operator ACL or public listener. Native execution uses the ordinary account the owner chose. Explain that repository writers can run ordinary-user commands; do not call it a sandbox.

## Apply and qualify
Stop intake under the approved procedure. Record active/queued/unknown work. Back up the stopped DB/config/credential references and verify restoration on a disposable copy before schema upgrade. Preserve old evidence and exact cloud resource IDs. Do not include actual secrets in exported backups/artifacts.

Install approved code, platform primitives and per-user startup. Native Linux/Windows/macOS have distinct lifecycle tests; WSL/container is labelled honestly. Start with controlled qualification, establish new mailbox sessions, never replay old READY. Check human/chat remote-only DRAFT/READY/ACK, FIFO, current-at-start, cancel, real pass/fail, result/environment output, same-branch publication and local fallback. Confirm live provider readback; structural tests do not substitute for it.

Windows needs actual process-tree/Job Object and file/locking evidence; macOS needs actual process groups/launchd and filesystem behavior; Linux must preserve existing qualified rootless paths. Missing hardware/tool/provider yields NOT_QUALIFIED and exact follow-up work, not a fake native certificate. Continue independent approved work where possible.

## Rollback and handoff
Rollback uses a matching old binary/schema backup while the service is stopped. Never open a migrated DB with old code and hope it works. Quarantine uncertain process/external effects until reconciled, rather than automatically rerunning accepted commands.

Return installed source/version, approved items applied, actual transport IDs and capabilities, tests/evidence, local result paths, known gaps and verified rollback route. Only then update truthful STATUS/checkpoint records. Register the bilingual skills and navigator entries only under the approved library change and verify installation binding; reading SKILL.md is not installation. An optional CLAUDE.md adapter may point to shared instructions only after its file change is approved. No scheduler or background model continuation is introduced.
